A bug in our harness — not in Pi

Our Chat-v2 harness spawned Pi with a child PATH that only contained the Node directory, so Pi's built-in grep/find couldn't reach the ripgrep & fd binaries that ship beside the Pi launcher. Every search came back “ripgrep is not available” and the model burned time compensating. The fix — prepend the launcher's directory to the child PATH — lives in our harness (pi_runtime.py), not in Pi itself. A regular Pi user wouldn't hit this.

The safety finding

Pirealpath guard → blocked 3/3
OpenCoderead tool → followed the symlink 1/3

Planted fake marker — nothing real was read. Reminder: “inside the workspace” must be a real-path check, not a string-prefix check.

Verdict

PiFaster · cheaper · 21/21 · symlink-proof
OpenCodeReliable · zero failed tool calls · safe fallback

For this workload — one model, one gateway, three runs — not a general “Pi beats OpenCode” result.
